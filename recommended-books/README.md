# Recommended Books

Curated list of essential books for staff software engineers, organized by category. Each book includes a summary, key takeaways, and why it matters for staff-level engineering.

## System Design

### 1. Designing Data-Intensive Applications by Martin Kleppmann
- **Summary**: The definitive guide to data systems — covers databases, distributed systems, batch/stream processing, and data modeling.
- **Key Takeaways**: Replication, partitioning, transactions, consistency, batch vs stream processing, lambda/kappa architecture.
- **Why read**: Best book for understanding the "why" behind system design decisions. Required reading for staff engineers.
- **Level**: Must read

### 2. System Design Interview by Alex Xu (Vol 1 & 2)
- **Summary**: Practical system design interview preparation with real-world case studies (Twitter, YouTube, Uber).
- **Key Takeaways**: Load balancing, caching, database sharding, message queues, CDN, system design framework.
- **Why read**: Best book for interview preparation. Clear diagrams and step-by-step design process.
- **Level**: Must read

### 3. Building Microservices by Sam Newman
- **Summary**: Comprehensive guide to microservices architecture, decomposition, deployment, and testing.
- **Key Takeaways**: Service decomposition, inter-service communication, data management, deployment patterns.
- **Why read**: Practical guide for teams adopting microservices. Covers pitfalls and anti-patterns.
- **Level**: Recommended

## Java

### 4. Effective Java by Joshua Bloch (3rd Edition)
- **Summary**: 90 best practices for writing production-quality Java code.
- **Key Takeaways**: Generics, lambdas, streams, concurrency, enums, builders, immutability.
- **Why read**: The Java bible. Every Java engineer should read it cover to cover.
- **Level**: Must read

### 5. Java Concurrency in Practice by Brian Goetz
- **Summary**: Comprehensive guide to Java concurrency — memory model, thread safety, concurrent collections.
- **Key Takeaways**: Immutability, confinement, synchronized, volatile, executors, concurrent collections.
- **Why read**: The definitive guide to Java concurrency. Essential for understanding thread safety.
- **Level**: Must read

### 6. Clean Code by Robert C. Martin
- **Summary**: Principles of writing clean, maintainable code with examples in Java.
- **Key Takeaways**: Meaningful names, small functions, SOLID principles, error handling, unit tests.
- **Why read**: Foundation for writing code that others can read and maintain.
- **Level**: Recommended

## Distributed Systems

### 7. Distributed Systems for Fun and Profit by Mikito Takada
- **Summary**: Free online book that explains distributed systems concepts with simple analogies.
- **Key Takeaways**: Replication, consistency, availability, message queues, distributed coordination.
- **Why read**: Best introduction to distributed systems. Read it in one sitting.
- **Level**: Must read (free online)

### 8. Site Reliability Engineering by Google
- **Summary**: Google's approach to production operations — SLOs, error budgets, incident management.
- **Key Takeaways**: SLO/SLI definition, error budgets, blameless postmortems, capacity planning.
- **Why read**: Defines modern SRE practices. Free online from Google.
- **Level**: Must read (free online)

## Career

### 9. The Staff Engineer's Path by Tanya Reilly
- **Summary**: Guide to transitioning from senior to staff engineer — technical leadership, influence, impact.
- **Key Takeaways**: Technical strategy, cross-team projects, mentoring, saying no, measuring impact.
- **Why read**: Best book for understanding what staff engineers actually do.
- **Level**: Must read for staff-level aspirants

### 10. Accelerate by Nicole Forsgren
- **Summary**: Research-backed guide to high-performing tech organizations — DORA metrics, DevOps practices.
- **Key Takeaways**: Deployment frequency, lead time, MTTR, change failure rate, team autonomy.
- **Why read**: Data-driven approach to engineering excellence. Shows what separates elite performers.
- **Level**: Recommended

## How to Use

1. **Start with "Must read" books**: DDD, System Design Interview, Effective Java, Java Concurrency in Practice
2. **Read actively**: Take notes, draw diagrams, implement examples
3. **Apply knowledge**: After each chapter, relate it to problems in this repository
4. **Discuss with team**: Book club format — discuss one chapter per week
